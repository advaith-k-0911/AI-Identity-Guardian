# AI Identity Guardian — Architecture Specification

This document details the system architecture, component boundaries, scoring methodologies, and design principles of **AI Identity Guardian**.

---

## 1. Architectural Overview

AI Identity Guardian employs a decoupled, modular architecture with a strict separation of concerns between presentation, API, core deterministic risk engines, scoring services, and storage.

```
┌─────────────────────────────────────────────────────────────┐
│                    Frontend (React + TS)                    │
│   Landing ── Identity Scan ── Dashboard ── Reports UI      │
└──────────────────────────────┬──────────────────────────────┘
                               │ JSON / REST (HTTPS)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                   Backend (FastAPI Layer)                   │
│   /api/v1/auth    /api/v1/analysis/*     /api/v1/reports    │
└──────────────┬──────────────────────────────┬───────────────┘
               │                              │
               ▼                              ▼
┌─────────────────────────────┐┌──────────────────────────────┐
│  Deterministic Risk Engines ││      Storage & Persistence   │
│  - Username Analysis Engine ││  - Normalized SQL Schemas    │
│  - Privacy Exposure Engine  ││  - Repository Pattern        │

```

## 2. Core Design Principles

### A. Authoritative Backend
The backend is the sole source of truth for risk calculations, score computation, and validation. The frontend consumes structured results and handles presentation only.

### B. Deterministic & Explainable Risk Engines
Every finding generated by the risk engines is:
- **Deterministic**: Given identical inputs, engines produce identical findings and scores.
- **Structured**: Consists of category, severity (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`), title, description, numerical score impact, and remediation steps.
- **Bounded**: All component scores and the aggregate DIESS score strictly range from **0 to 100**.

### C. Layered AI Explanation
AI models act purely as an explanatory and translation layer on top of deterministic findings:
1. Deterministic Engine generates structured findings.
2. AI Layer translates findings into clear, tailored, contextual explanations and prioritized guidance.
3. AI is prevented from hallucinating or inventing non-existent vulnerabilities.

## 3. Data Flow & Scoring: DIESS

The **Digital Identity Exposure & Security Score (DIESS)** combines multiple security dimensions using a weighted model:

$$\text{DIESS} = w_{\text{user}} S_{\text{user}} + w_{\text{priv}} S_{\text{priv}} + w_{\text{imp}} S_{\text{imp}} + w_{\text{cred}} S_{\text{cred}} + w_{\text{rec}} S_{\text{rec}}$$

### Default Weight Distribution
| Dimension | Weight | Description |
| :--- | :---: | :--- |
| **Username Security** | 20% | Detects personal identifiable information (PII) leakage in usernames |
| **Privacy Security** | 25% | Evaluates exposure, sensitivity, and necessity of personal profile data |
| **Impersonation Security** | 20% | Assesses attack surface for impersonation / social engineering |
| **Credential Security** | 20% | Evaluates password practices and authentication factors (transient) |
| **Recovery Security** | 15% | Evaluates backup channel resiliency and recovery security questions |

---

## 4. Structured Finding Schema

Every finding follows a standardized schema:

```json
{
  "id": "FINDING-USR-001",
  "category": "USERNAME_PII_LEAK",
  "severity": "HIGH",
  "title": "Full Name Exposed in Username",
  "description": "The analyzed username contains elements of your first or last name.",
  "score_impact": 25.0,
  "recommendation": "Use pseudonymous handles that do not mirror your legal name or initials."
}
```

---

## 5. Security & Privacy Guarantees

1. **Transient Analysis**: Sensitive parameters are analyzed in memory and immediately discarded.
2. **Zero Plaintext Password Retention**: Passwords analyzed for credential hygiene are evaluated transiently and never stored in any database or log.
3. **Defense in Depth**: Pydantic input sanitization, parameterized queries (SQLAlchemy ORM), secure HTTP headers, and strict CORS policies.
